# "Hands up!" - уязвимость системы ладошки со статическими ключами
**By:** @Vulndisclosure 

[Read in English 🇺🇸](README.md)

**Проблемма:**
1. Статические ключи в формате FFFFFFFFFFFF
2. Определение и идентификация пользователя в системах оплаты и контроля доступа является только использование UID
3. Отсутствие диверсификации ключей 
4. Использование небезопасного стандарта с отсутствием шифрования в критической инфраструктуре 

**Соответвующие CWE:**
- CWE-798: Use of Hard-coded Credentials
- CWE-1391: Use of Weak Credentials
- CWE-287: Improper Authentication
- CWE-290: Authentication Bypass by Spoofing

**Что уязвимо:**
Все карты и браслеты ладошки

**Объяснения:**
Из дампа карты можно понять, что каждый экземпляр отличается только его UID, и использует статический ключ "FFFFFFFFFFFF", что позволяет атакующему при чтении карты:
1. Проходить через турникеты, выдавать себя за школьника
2. Использовать украденный UID для эмуляции транзакций

По сути в системе физического доступа отсутствует какая-либо аутентификация, только идентификация 

Проблема не в том, что "ключи плохие", а в том, что финансовая операция доверяет незащищенному идентификатору:

1. **Идентификация:** UID карты (публичная информация).
2. **Аутентификация:** Отсутствует (ключи дефолтные, сектор 0 доступен всем).
3. **Авторизация:** Происходит на сервере только на основании UID.

**PoC:**
(Пикчи дампа)

На скриншоте условий доступа (Access Conditions) видно, что все сектора управляются стандартным ключом. Столбцы Read/Write подтверждают возможность манипуляции данными блоков без использования проприетарных алгоритмов шифрования, что делает систему беззащитной перед любым NFC-совместимым устройством

**Мы видим:**
- UID - главный идентификатор
- Ключ A - FFFFFFFFFFFF 
- Ключ B - FFFFFFFFFFFF 
- И условия доступа

Это фундаментальная ошибка не только в бизнес логике, но и системе пропусков, так как системе доверяют миллионы людей и пользуются ей каждый день
